# Протокол роботи з прошивками

## 1. Зберігання

Для кожної прошивки зберігаємо:

- `product`;
- `hardware`;
- `version`;
- файл;
- `SHA-256`;
- `state`;
- ще можна додати опис оновлення для відображеня у додатку.

Комбінація `product + hardware + version` повинна відповідати одному конкретному файлу.

Поле `state` одночасно визначає стан прошивки та канали, у яких вона доступна.

Допускаються тільки такі значення:

```text
beta_draft
beta_published
beta_withdrawn
beta_stable_published
beta_stable_withdrawn
```

Після першої публікації файл, `version` і `SHA-256` змінювати не можна.

Якщо файл змінився, створюється нова версія.

## 2. Завантаження

Адміністратор завантажує файл і вказує:

- `product`;
- `hardware`;
- `version`.

Канал окремо вибирати не потрібно. Нова прошивка завжди створюється у стані:

```text
beta_draft
```

Сервер:

- перевіряє, що файл не порожній;
- перевіряє допустимий розмір;
- перевіряє формат і підпис прошивки;
- перевіряє відповідність `hardware` і `version`;
- сам обчислює `SHA-256`;
- створює запис у стані `beta_draft`.

Якщо перевірка не пройдена, файл не зберігається.

## 3. Видалення

Повністю видалити можна тільки прошивку у стані:

```text
beta_draft
```

Після першої публікації прошивка вже не видаляється.

## 4. Публікація в beta

Після ручної перевірки прошивка переводиться:

```text
beta_draft → beta_published
```

Після цього вона доступна в каналі `beta`.

Окремо можна вказати її як поточну версію для:

```text
product + hardware + beta
```

Для цієї комбінації може бути тільки одна поточна версія.

## 5. Публікація в stable

У `stable` можна опублікувати тільки прошивку, яка вже опублікована в `beta`:

```text
beta_published → beta_stable_published
```

Повторно завантажувати файл не потрібно.

`version` і `SHA-256` не змінюються.

Після цього та сама прошивка доступна одночасно в каналах `beta` і `stable`.

Окремо можна вказати її як поточну версію для:

```text
product + hardware + stable
```

Поточні версії для `beta` і `stable` визначаються окремо.

## 6. Отримання інформації про оновлення

Додаток отримує з сервера актуальну версію для комбінації:

```text
product + hardware + channel
```

Для каналу `beta` сервер може використовувати прошивки у станах:

```text
beta_published
beta_stable_published
```

Для каналу `stable` сервер може використовувати тільки прошивки у стані:

```text
beta_stable_published
```

Додаток передає сигналізації тільки `version`.

`product` сигналізація бере з `FWUPDATE_PRODUCT`, а `hardware` — з `CONFIG_BOARD`.

## 7. Зняття з публікації

Прошивку, доступну тільки в `beta`, можна зняти переходом:

```text
beta_published → beta_withdrawn
```

Прошивку, доступну в `beta` і `stable`, можна зняти переходом:

```text
beta_stable_published → beta_stable_withdrawn
```

У другому випадку прошивка знімається одразу з обох каналів.

Після зняття прошивка:

- не пропонується додаткам;
- не може залишатися поточною версією;
- не віддається для нового оновлення.

`withdrawn` - це кінцевий статус

## 8. Дозволені переходи

```text
beta_draft → delete
beta_draft → beta_published

beta_published → beta_withdrawn
beta_published → beta_stable_published

beta_stable_published → beta_stable_withdrawn
```

Інші переходи не допускаються.
